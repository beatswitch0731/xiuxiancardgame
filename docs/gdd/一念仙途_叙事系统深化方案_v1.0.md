# 一念仙途·叙事系统深化方案 v1.0

> **设计目标**：在现有四引擎弧线系统 + 因果系统基础上，补上三个叙事维度——NPC交叉互动、环境叙事（卡牌游戏适配版）、选择延迟回响。让游戏从"你和NPC的故事"变成"你、NPC、世界三者交织的故事"。

---

## 一、NPC 交叉互动系统（CrossInteractionEngine）

### 1.1 现状

| 有的 | 没有的 |
|------|--------|
| NpcSystem 有 `this.npcs`（8个NPC完整数据）| NPC之间无任何关系数据 |
| NpcSystem 有 `this.locations`（NPC当前位置）| 两个NPC在同一位置时不产生任何事 |
| NpcSystem 有日程系统（6时辰 × 位置映射）| 日程只用于 NPC-玩家遭遇文本 |
| NPC遭遇卡优先级30（单人，概率15%）| 无双人/多人 NPC 互动卡 |
| 好感/羁绊/信任全是对玩家的 | NPC彼此的好感不存在 |

**致命体验空洞**：白刃真人和血煞老祖都在"宗门"——剑道宗师和魔道老祖同处一室，玩家看不到任何互动。

### 1.2 设计方案

#### 1.2.1 NPC关系矩阵（NpcRelationMatrix）

数据结构——存在 `NpcSystem` 里，与 `this.npcs` 同级：

```javascript
// npcIdA → npcIdB → relationData
this.npcRelations = new Map();

// relationData 结构：
{
  affinity: -100~100,      // NPC间好感（独立于玩家好感）
  history: [],             // 交互历史快照 [{turn, event, delta}]
  status: 'neutral'|'rival'|'ally'|'master-disciple'|'estranged',
  lastInteractionTurn: 0,
  sharedSecrets: []        // NPC间共享的秘密（玩家不知道的）
}
```

**初始关系预设**（8个NPC间的关键连线）：

| NPC A | NPC B | affinity | status | 故事理由 |
|-------|-------|----------|--------|---------|
| 白刃真人 | 剑灵儿 | +50 | master-disciple | 剑灵儿是白刃的关门弟子 |
| 白刃真人 | 血煞老祖 | -60 | rival | 正魔对立，百年恩怨 |
| 白刃真人 | 天机老人 | +30 | ally | 曾联手对抗天劫 |
| 天机老人 | 九尾溯月 | -20 | estranged | 天机老人曾预言九尾一族覆灭 |
| 天机老人 | 白刃真人 | +30 | ally | 互为见证 |
| 血煞老祖 | 殷血 | +70 | master-disciple | 殷血出身血煞魔宫 |
| 血煞老祖 | 慕青岚 | -40 | rival | 慕家被魔道清洗，血煞在场 |
| 剑灵儿 | 慕青岚 | +20 | ally | 同为正道女修，惺惺相惜 |
| 白落霜 | 九尾溯月 | +40 | ally | 同为妖族/半妖血脉 |
| 殷血 | 剑灵儿 | -30 | rival | 正魔天然对立 + 都暗恋玩家 |
| 慕青岚 | 天机老人 | +10 | neutral | 慕家曾向天机老人问卦 |

> 注意：只有 12 条关键关系。不是 8×8=56 条全填——关系稀疏但每条有故事。其他组合默认 `{affinity:0, status:'neutral'}`。

#### 1.2.2 位置重合检测（LocationOverlap）

原理：每次 NPC 日程更新（`_tick` 里 `getCurrentSchedule`）后，检测所有在同一位置的 NPC 对。

```javascript
// 每轮 tick 时调用
_checkCrossInteractions() {
  const locationMap = {}; // location → [npcId, npcId, ...]
  for (const [npcId] of this.npcs) {
    const loc = this.getCurrentSchedule(npcId);
    if (!locationMap[loc]) locationMap[loc] = [];
    locationMap[loc].push(npcId);
  }

  for (const [loc, npcIds] of Object.entries(locationMap)) {
    if (npcIds.length < 2) continue;
    // 查找所有 pair
    for (let i = 0; i < npcIds.length; i++) {
      for (let j = i + 1; j < npcIds.length; j++) {
        this._tryTriggerNpcInteraction(npcIds[i], npcIds[j], loc);
      }
    }
  }
}
```

#### 1.2.3 触发条件与概率

```
基础触发概率 = 15%（与单人遭遇相同）
修正因子：
  × 1.5  如果两个NPC有预设关系（affinity ≠ 0）
  × 2.0  如果两个NPC的关系status是 'rival' 且同处一室（戏剧性优先）
  × 0.5  如果该对NPC过去10轮内已有交互（冷却）
  × 1.3  玩家福缘修正
  × 1.5  如果当前场景是"宗门大殿"（高密聚地点，戏剧浓度高）
```

#### 1.2.5 玩家影响 NPC 间关系

现有系统：玩家好感变化 → `companion:affectionChange` → 道侣弧线推进。

新增通道：玩家选择可以影响 NPC 间关系 → `npc:relationChanged` → 触发后续 NPC 交叉卡。

效果字段格式：`'npc_relation:npcA:npcB': delta`

```javascript
// game.js makeChoice() 中新增处理分支
if (choice.effects) {
  for (const [key, value] of Object.entries(choice.effects)) {
    if (key.startsWith('npc_relation:')) {
      const [, npcA, npcB] = key.split(':');
      npcSystem.adjustNpcRelation(npcA, npcB, value);
    }
  }
}
```

#### 1.2.6 NPC关系变化的连锁反应

```
玩家调解了白刃vs血煞的冲突
  → npc_relation:bai_ren:xue_sha +10
  → 触发白刃真人对玩家的好感微增（"你倒是公允"）
  → 触发血煞老祖的同盟度微增（"小子有种"）
  → 如果关系从 -60 改善到 -30 以上
    → 解锁新的 NPC_CROSS 卡：白刃与血煞的"短暂的休战"
    → 世界标签新增：'white_red_truce'
```

## 二、环境叙事系统（SceneLayerSystem）

### 2.1 核心思路

**卡牌游戏的环境叙事 ≠ 3D场景的props/lighting。**

在卡牌游戏中，环境叙事 = **场景状态机 + 位置叙事层 + 视觉氛围卡**。

玩家看不到3D空间，但可以通过以下方式"感受"位置：
- **场景卡**：进入新位置时弹出，展示位置美术 + 文字描述
- **叙事层叠加**：同一位置多次访问，揭示不同深度的信息
- **位置状态变迁**：关键事件后，同一位置"看起来不一样了"

### 2.2 设计方案

#### 2.2.1 三层位置体系

```
Tier 1 — 六道·主场景（必有）
  宗门 / 坊市 / 秘境入口 / 洞府 / 魔域 / 天道虚空

Tier 2 — 细粒度位置（NPC日程使用）
  宗门大殿 / 藏经阁 / 炼丹房 / 后山竹林 / 剑崖 / 天机阁

Tier 3 — 隐藏/特殊位置（剧情解锁）
  白落霜的狐丘 / 血煞老祖的地宫密室 / 天道裂缝
```

**GameStateManager 新增字段**：

```javascript
this.currentLocation = '宗门';           // 当前位置
this.visitedLocations = ['宗门'];         // 已访问位置
this.locationStates = {                  // 位置叙事状态
  '宗门大殿': { visits: 3, layer: 2, eventFlags: ['bai_ren_departed'] }
};
```

#### 2.2.2 场景卡（LocationCard）

类型 `LOCATION`，注入优先级 **28**（SHOP 25 之下，NORMAL 10 之上）。

触发时机：
- **强制触发**：首次进入新位置、主线推进换场景
- **概率触发**：已在某位置多轮，概率弹出"深度观察"卡

#### 2.2.3 位置状态变迁

关键事件后，位置"换皮"——同样的位置，不同的描述，不同的情感基调。

```
剑崖（白刃真人去世前）
  → 描述：剑气纵横，庄严
  → 可触发：白刃真人传授剑法卡

剑崖（白刃真人去世后）
  → 描述：剑气消散，崖壁开始风化。那只"白"字的情书，现在读来，字字如泪。
  → 可触发：玩家独自悟剑卡 + 白刃遗物发现卡
```

实现：位置状态字段 `locationStates['剑崖'].eventFlags` 包含 `'bai_ren_departed'` 时，`_getLocationCard()` 返回不同版本。

#### 2.2.4 环境叙事与卡牌视觉

当前项目是像素风，卡牌本身有美术。环境叙事不只在文字——**卡牌的背景色调、边框纹样、粒子效果**都能传递位置感：

| 位置 | 卡牌背景色调 | 边框纹样 | 氛围 |
|------|------------|---------|------|
| 宗门 | 暖金 + 白 | 云纹 | 庄严光明 |
| 坊市 | 暖棕 + 灯笼红 | 铜钱纹 | 热闹喧嚣 |
| 秘境 | 冷蓝 + 紫 | 符文 | 神秘危险 |
| 魔域 | 暗红 + 黑 | 骨纹 | 压抑邪异 |
| 天道虚空 | 透明 + 星点 | 无边框 | 超脱虚无 |

这需要在 UI 层实现——当 `gameState.currentLocation` 变化时，卡牌渲染应用对应的 CSS 类名。

## 三、选择延迟回响系统（ChoiceEchoEngine）

### 3.1 与 KarmaSystem 的区别

| | KarmaSystem（因果） | ChoiceEcho（回响） |
|---|---|---|
| 本质 | 因果报应：做善得善，做恶得恶 | 叙事共鸣：选择被世界记住 |
| 延迟 | 种子发芽 = 事件发生 | 选择被引用 = 情感确认 |
| 效果 | 数值变化 + 新事件 | 文本引用 + 情感连续性 |
| 例子 | 你杀了某人 → 20轮后仇家上门 | 你曾选择相信她 → 50轮后她提起这件事 |
| 存储 | KarmaSeed 对象 | EchoRecord 对象 |

**KarmaSystem 是"后果"，ChoiceEcho 是"回音"。**

### 3.2 设计方案

#### 3.2.1 回响存储（EchoRecord）

每次玩家做选择，存储一条回响记录：

```javascript
// 存在 GameStateManager 中
this.choiceEchoes = [];

// EchoRecord 结构：
{
  id: 'echo_001',
  turn: 12,                    // 选择发生在第12轮
  realm: 'foundation',         // 当时的境界
  cardId: 'bai_luoxuan_stage_2',
  choice: 'left',              // 选了左边
  choiceLabel: '接过参汤',     // 选项文本摘要
  context: {                   // 选择时的上下文
    npcId: 'bai_luoxuan',
    affection: 35,
    location: '宗门大殿'
  },
  echoConditions: {            // 回响触发条件
    minTurnGap: 20,           // 至少20轮后才回响
    minAffection: 60,         // 好感≥60时触发（关系升温了）
    npcAlive: true,
    location: '宗门大殿'      // 同一位置触发效果更佳
  },
  echoText: '白落霜端来一碗参汤，和那年初见时一模一样。\n她没说话，但眼神在问——你还会喝吗。',
  echoChoices: {
    left:  { text: '接过，一饮而尽', effects: { affection: 10, bond: 1 } },
    right: { text: '推回去，"我不需要被照顾了"', effects: { affection: -5, independence: 3 } }
  },
  triggered: false
}
```

#### 3.2.2 回响写入

在 `game.js` 的 `makeChoice()` 中，每次玩家做选择后调用：

```javascript
// 在 makeChoice 末尾添加
if (card.type && card.npcId) {
  // 只对道侣/师尊/盟友/先知的弧线卡做回响
  const echoTypes = ['COMPANION_ARC', 'COMPANION_EVENT', 'MENTOR_ARC', 'ALLY_ARC'];
  if (echoTypes.includes(card.type)) {
    storyNetworkSystem.choiceEchoes.plantEcho({
      turn: gameState.turn,
      realm: gameState.realm,
      cardId: card.id,
      choice: chosenSide,  // 'left' | 'right'
      choiceLabel: choice.text,
      npcId: card.npcId,
      affection: companionSystem ? (companionSystem.companions[card.npcId]?.affection || 0) : 0,
      location: gameState.currentLocation || '未知',
      cardType: card.type
    });
  }
}
```

#### 3.2.3 回响生成

每轮结束时，`ChoiceEchoEngine` 扫描所有未触发的回响，检查条件：

```javascript
class ChoiceEchoEngine {
  checkAndGenerate() {
    for (const echo of gameState.choiceEchoes) {
      if (echo.triggered) continue;
      if (!this._checkConditions(echo)) continue;

      // 条件满足，生成回响卡
      const card = this._buildEchoCard(echo);
      echo.triggered = true;
      eventBus.emit('storynetwork:narrativeCard', {
        card,
        priority: 36,  // 略高于叙事浮现(35)，低于先知推进(39)
        source: 'choice_echo'
      });
      break; // 每轮最多触发一个回响（避免轰炸）
    }
  }

  _checkConditions(echo) {
    const c = echo.echoConditions;
    if (gameState.turn - echo.turn < c.minTurnGap) return false;
    if (c.minAffection) {
      const aff = companionSystem?.companions[echo.context.npcId]?.affection || 0;
      if (aff < c.minAffection) return false;
    }
    if (c.npcAlive && gameState.deadNpcs?.includes(echo.context.npcId)) return false;
    if (c.location && gameState.currentLocation !== c.location) return false;
    return true;
  }

  _buildEchoCard(echo) {
    return {
      id: `echo_${echo.id}`,
      type: 'CHOICE_ECHO',
      title: `……${echo.turn}轮前`,
      description: echo.echoText,
      npcId: echo.context.npcId,
      originTurn: echo.turn,
      originChoice: echo.choiceLabel,
      once: true,
      weight: 0,
      tags: ['echo', 'memory'],
      choices: echo.echoChoices
    };
  }
}
```

#### 3.2.4 回响卡示例

```
第12轮，玩家选择了[接过参汤]（白落霜·相知阶段）
第50轮，好感从35涨到了65，位置再次回到宗门大殿

弹出回响卡：
┌─────────────────────────────────────┐
│  ……12轮前                           │
│                                     │
│  白落霜端来一碗参汤，和那年初见时   │
│  一模一样。她没说话，但眼神在问——   │
│  你还会喝吗。                       │
│                                     │
│  [接过，一饮而尽]  [推回去]         │
└─────────────────────────────────────┘
```

#### 3.2.5 回响的情感设计原则

| 原则 | 说明 |
|------|------|
| **不解释** | 回响文本不重复当初发生了什么，只展示"现在" |
| **情感递进** | 第一次选"接过"—信任建立。回响选"接过"—承诺确认 |
| **对比张力** | 第一次选"相信她"—天真。回响已知真相——选择更重 |
| **反向回响** | 第一次选"背叛她"—现在她回来了，气氛完全不同 |

## 五、叙事质量——如何"打动人"

### 5.1 原则

> **不是"加了三个系统"，而是"玩家能感受到三种体验"。**

| 系统 | 玩家感受 | 检验标准 |
|------|---------|---------|
| NPC交叉互动 | "这世界不是围着我转的——他们有自己的恩怨" | 玩家能说出两组NPC之间的关系 |
| 环境叙事 | "这个地方有故事，不只是背景" | 玩家能描述一个场景的"感觉" |
| 选择回响 | "我做的事被世界记住了" | 玩家在看到回响卡时能想起当时的场景 |

### 5.2 第一批内容优先级

**先做 6 张最有力的卡**（不贪多，张张有记忆点）：

1. **NPC交叉**：白刃真人 vs 血煞老祖·宗门对峙（剑拔弩张）
2. **NPC交叉**：殷血 vs 剑灵儿·暗巷相遇（情敌修罗场）
3. **场景卡·Tier1**：剑崖初见（白刃的剑气世界）
4. **场景卡·Tier2**：剑崖深层（白刃的情书秘密）
5. **选择回响**：白落霜的参汤（全游戏最温暖的那碗汤）
6. **选择回响**：慕青岚的书卷（你曾选择"一起查"还是"替她查"）

### 5.3 文本质量标准

每张叙事卡必须经过三道检验：

1. **"真实人物"检验**：这句话像角色说的话，还是像作者的解释？
2. **"情感层次"检验**：读完后，玩家不只是"知道了"，而是"感受到了"？
3. **"游戏后果"检验**：选了左边和选了右边，在数值/状态上有可感知的差异吗？
