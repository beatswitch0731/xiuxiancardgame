> 日期：2026-07-01

> 前置文档：`修仙卡牌决策游戏GDD_v0.5.md` · `王权系列玩法剖析与创新方向.md` · `一念仙途_系统改进执行方案_v2.0.md`

## 一、核心诊断：为什么你的游戏"不像一个游戏"

### 1.1 病症描述

玩家反馈："玩游戏也不知道在玩什么"、"卡牌逻辑流程串不起来"、"bug多"。

### 1.2 根因定位

打开 `game.js` 的 `getCurrentCard()` 和 `CardSystem.js` 的 `draw()`，你会看到**两套互相打架的卡牌调度系统**：

**系统A — game.js 的 7 个 pending 标志位**：
```
_inCombat → _innerDemonActive → destinyWheelSystem.active → 
_pendingRipple → _pendingHint → _pendingMarket → _chapterMilestoneCard → 
_narrativeQueue → cardSystem.draw()
```

**系统B — CardSystem.js 的 9 级优先级链**：
```
P100(死亡) → 秘境 → P90(突破) → P80(支线当前) → P70(支线入口) → 
P60(因果发芽) → P55-42(重大叙事, 预算门控) → P40-28(次要叙事, 预算门控) → 
P25(商店) → P20(集市) → P10(普通卡)
```

**这两套系统同时存在，互相覆盖**。game.js 的 `_narrativeQueue` 在 CardSystem 的 9 级链之前执行，会直接截断 CardSystem 的所有逻辑。而 CardSystem 内部又有一套独立的叙事预算系统，控制 StoryNetworkSystem 的注入。

结果就是：**没有一个统一的"导演"来决定"这一刻玩家应该看到什么"**。15 个子系统各自往队列里推卡，玩家看到的是一堆来源不明、节奏混乱的卡牌堆叠。

### 1.3 对比：成熟游戏怎么做的

| 游戏 | 流转架构 | 核心设计 |
|------|----------|----------|
| **王权 Reigns** | 单一 Bag 系统 | 一个权重袋，根据当前状态调整卡牌权重，自然涌现叙事 |
| **杀戮尖塔 StS** | 地图节点 → 节点类型 → 卡牌池 | 玩家在地图上选路，每个节点类型（战斗/精英/休息/商店/事件/宝箱）有明确的卡牌来源 |
| **Balatro** | 回合结构（小盲注→大盲注→Boss盲注） | 每个回合有清晰目标，卡牌来源单一（玩家手牌+购买的小丑牌） |
| **一念仙途（现状）** | 15个子系统各自推卡 + 两套调度系统互打 | 无统一编排，卡牌来源不可读，玩家无法形成"我在做什么"的认知 |

## 二、市面同类游戏的核心流转逻辑拆解

### 2.1 王权：为什么简单却好玩

王权的核心不是"左右滑动"，而是**Bag 系统**创造的涌现感：

```
状态变化 → 调整Bag中卡牌权重 → 抽卡 → 状态变化 → 循环
```

关键设计：
- **只有一个调度器**：Bag 系统。没有第二个队列、没有 pending 标志位
- **权重即叙事**：发动战争后，战争相关卡牌权重飙升，玩家自然感受到"战争还在持续"
- **子系统是"锁入"模式**：地牢/恶魔交易是独立模式，进入后暂时替换主循环，退出后恢复
- **死亡解锁 = 扩大Bag**：每次死亡往袋子里加新卡，重玩有新内容

### 2.2 杀戮尖塔：为什么有策略深度

杀戮尖塔的核心不是"卡组构筑"，而是**地图选择 + 节点类型**给玩家的控制感：

```
Act结构 → 地图路径选择 → 节点类型确定 → 节点内卡牌来源明确 → 奖励 → 下一个节点
```

关键设计：
- **玩家选路**：地图上有多条路径，玩家主动选择走战斗路还是商店路
- **节点类型 = 卡牌来源**：战斗节点抽战斗卡，事件节点抽事件卡，商店节点进商店。来源永远清晰
- **奖励明确**：战斗胜利后选择1张卡加入牌组。玩家有主动权
- **Boss门可见**：玩家始终知道下一个目标是什么

### 2.3 共同规律：成熟卡牌游戏的"三定律"

从这三款游戏提炼出来的共同规律：

| 定律 | 含义 | 一念仙途违反了吗 |
|------|------|------------------|
| **单一调度器** | 只有一个系统决定"下一张是什么" | 违反 — 有两套系统互打 |
| **来源可读** | 玩家能推断"这张卡为什么出现" | 违反 — 15个系统各自推卡，玩家无从判断 |
| **目标可见** | 玩家始终知道"下一步要做什么" | 违反 — 只有修为条，无短期目标 |

## 三、重构方案：Flow Director 架构

### 3.1 核心理念

引入一个**唯一的卡牌调度器** — `FlowDirector`，取代现有的 game.js pending 标志位 + CardSystem 9级链双系统。

FlowDirector 的工作模式：

```
每轮决策结束后 → FlowDirector.evaluate() → 判断当前"场景阶段" → 
  按阶段规则选择卡牌来源 → 返回一张卡 → 玩家做选择 → 循环
```

### 3.2 场景阶段（Scene Phase）系统

FlowDirector 的核心是**场景阶段**概念。玩家在任意时刻处于且仅处于一个场景阶段，不同阶段有不同的卡牌来源权重：

| 阶段 | 触发条件 | 主卡牌来源 | 玩家感受 |
|------|----------|------------|----------|
| `CALM` 平静期 | 刚进入新境界 / 刚结束战斗 | 普通卡池(70%) + 轻叙事(20%) + 商店(10%) | "探索世界，积累资源" |
| `BUILDUP` 蓄力期 | 修为达到40%+ | 普通卡池(50%) + 因果发芽(25%) + 支线(15%) + 轻叙事(10%) | "事情开始多起来了" |
| `TENSION` 紧张期 | 修为达到70%+ / 因果种子即将发芽 | 因果发芽(35%) + 里程碑(25%) + 普通卡(25%) + 叙事(15%) | "大事要发生了" |
| `CLIMAX` 高潮期 | 里程碑触发 / 突破 / Boss战 | 里程碑卡(60%) + 支线高潮(30%) + 普通卡(10%) | "关键时刻" |
| `RESOLUTION` 收束期 | 高潮事件后2-3轮 | 轻叙事(40%) + 普通卡(50%) + 商店(10%) | "喘口气，整理收获" |
| `DUNGEON` 秘境期 | 进入秘境 | 秘境节点卡(100%) | "探索秘境" |
| `COMBAT` 战斗期 | 战斗卡触发 | 战斗系统接管 | "战斗中" |

### 3.3 阶段转换规则

```
                    ┌─────────────────────────────────┐
                    │                                 │
                    ▼                                 │
新境界开始 → CALM → BUILDUP → TENSION → CLIMAX → RESOLUTION
                ↑                                    │
                └────────────────────────────────────┘
                          (回到CALM)

特殊中断（随时可插入）：
  DUNGEON → 秘境结束后回到原阶段
  COMBAT → 战斗结束后回到原阶段
```

转换条件：
- `CALM → BUILDUP`：修为达到当前境界的 40%
- `BUILDUP → TENSION`：修为达到 70%，或有因果种子即将发芽
- `TENSION → CLIMAX`：里程碑阈值触发，或玩家主动选择"冲击瓶颈"
- `CLIMAX → RESOLUTION`：高潮卡牌处理完毕（通常1-3张）
- `RESOLUTION → CALM`：收束期持续2-3轮后自动转回

### 3.4 与现有系统的映射

| 现有系统 | 在 FlowDirector 中的角色 | 变化 |
|----------|--------------------------|------|
| CardSystem._drawNormal() | CALM/BUILDUP 的普通卡来源 | 保留，去掉9级优先级链 |
| StoryNetworkSystem | 各阶段的叙事卡供应商 | 不再直接推卡到队列，改为被 FlowDirector 查询 |
| CompanionSystem | 叙事卡供应商 | 同上 |
| QuestSystem | BUILDUP/TENSION 的支线卡来源 | 保留，由 FlowDirector 按阶段决定是否查询 |
| KarmaSystem | TENSION 阶段的因果发芽来源 | 保留 |
| RealmChapterSystem | CLIMAX 阶段的里程碑来源 | 保留 |
| ShopSystem | CALM/RESOLUTION 阶段的商店来源 | 保留 |
| CombatSystem | COMBAT 阶段接管 | 保留 |
| DestinyWheel/LegacyFragment/KarmaRipple/HeavensHint/Market | 特殊事件，由 FlowDirector 统一管理触发时机 | 从 game.js 的 pending 标志位迁移到 FlowDirector |
| `_narrativeQueue` | 废除 | 由 FlowDirector 的阶段查询取代 |

## 四、FlowDirector 详细设计

### 4.1 数据结构

```javascript
const FlowDirector = {
  // 当前场景阶段
  currentPhase: 'CALM',
  
  // 阶段历史（用于转换判断）
  phaseHistory: [],
  
  // 阶段内轮数计数
  turnsInPhase: 0,
  
  // 高潮队列（CLIMAX阶段依次弹出）
  climaxQueue: [],
  
  // 收束队列（RESOLUTION阶段依次弹出）
  resolutionQueue: [],
  
  // 特殊事件队列（秘境/战斗/命盘等，最高优先级）
  interruptQueue: [],
  
  // 全局轮数
  globalTurns: 0,
};
```

### 4.2 核心方法：evaluate()

每次需要新卡时，FlowDirector.evaluate() 被调用：

```javascript
evaluate() {
  this.globalTurns++;
  this.turnsInPhase++;
  
  // 第0层：特殊中断（秘境/战斗/命盘等）— 最高优先级
  if (this.interruptQueue.length > 0) {
    return this.interruptQueue.shift();
  }
  
  // 第1层：战斗中 — 战斗系统接管
  if (gameState._inCombat) {
    return { type: 'COMBAT_UI', combatState: combatSystem.getState() };
  }
  
  // 第2层：秘境模式 — 秘境节点卡
  if (gameState.dungeon) {
    return cardSystem._drawDungeonCard();
  }
  
  // 第3层：阶段驱动的卡牌选择
  this._updatePhase();
  
  switch (this.currentPhase) {
    case 'CLIMAX':
      if (this.climaxQueue.length > 0) {
        return this.climaxQueue.shift();
      }
      // 高潮队列空了 → 转入收束
      this._transitionTo('RESOLUTION');
      return this._drawForPhase('RESOLUTION');
    
    case 'RESOLUTION':
      if (this.resolutionQueue.length > 0) {
        return this.resolutionQueue.shift();
      }
      // 收束队列空了 → 转回平静
      this._transitionTo('CALM');
      return this._drawForPhase('CALM');
    
    default:
      return this._drawForPhase(this.currentPhase);
  }
}
```

### 4.3 阶段驱动抽卡：_drawForPhase()

```javascript
_drawForPhase(phase) {
  // 每个阶段有一个"卡牌来源权重表"
  const sources = PHASE_SOURCES[phase];
  
  // 按权重随机选择一个来源
  const roll = Math.random() * 100;
  let accumulator = 0;
  
  for (const [source, weight] of Object.entries(sources)) {
    accumulator += weight;
    if (roll < accumulator) {
      const card = this._drawFromSource(source);
      if (card) return card;
    }
  }
  
  // 所有指定来源都无卡 → 回退到普通卡池
  return cardSystem._drawNormal();
}
```

### 4.4 阶段来源权重表

```javascript
const PHASE_SOURCES = {
  CALM: {
    normal:      70,   // 普通卡池（修炼/采集/日常）
    lightStory:   15,  // 轻叙事（NPC闲聊/环境描写）
    shop:         10,  // 商店
    companion:     5,  // 道侣日常互动
  },
  BUILDUP: {
    normal:      45,
    karma:        20,  // 因果种子发芽
    quest:        15,  // 支线推进
    lightStory:   10,
    companion:     5,
    shop:          5,
  },
  TENSION: {
    karma:        30,
    milestone:    25,  // 章节里程碑
    normal:       20,
    heavyStory:   15,  // 重大叙事（弧线推进）
    quest:        10,
  },
  CLIMAX: {
    milestone:    60,  // 里程碑卡为主
    heavyStory:   30,  // 弧线高潮
    normal:       10,
  },
  RESOLUTION: {
    lightStory:   35,
    normal:       40,
    shop:         15,
    companion:    10,
  },
};
```

### 4.5 阶段转换逻辑

```javascript
_updatePhase() {
  const realm = gameState.realm;
  const cultivation = gameState.attributes.cultivation;
  
  switch (this.currentPhase) {
    case 'CALM':
      // 平静期 → 修为达到40%进入蓄力期
      if (cultivation >= 40) {
        this._transitionTo('BUILDUP');
      }
      // 特殊：因果种子即将发芽 → 直接跳到紧张期
      if (karmaSystem.hasPendingBloom()) {
        this._transitionTo('TENSION');
      }
      break;
    
    case 'BUILDUP':
      // 蓄力期 → 修为达到70%进入紧张期
      if (cultivation >= 70) {
        this._transitionTo('TENSION');
      }
      // 支线任务激活 → 进入紧张期
      if (questSystem.hasActiveQuest()) {
        this._transitionTo('TENSION');
      }
      break;
    
    case 'TENSION':
      // 紧张期 → 里程碑触发进入高潮
      if (chapterSystem.shouldTriggerMilestone(realm, cultivation)) {
        this._enqueueMilestone(realm, cultivation);
        this._transitionTo('CLIMAX');
      }
      break;
    
    case 'RESOLUTION':
      // 收束期 → 2-3轮后回到平静
      if (this.turnsInPhase >= 3) {
        this._transitionTo('CALM');
      }
      break;
  }
}

_transitionTo(newPhase) {
  this.phaseHistory.push(this.currentPhase);
  this.currentPhase = newPhase;
  this.turnsInPhase = 0;
  
  // 进入高潮期时，预填充高潮队列
  if (newPhase === 'CLIMAX') {
    this._fillClimaxQueue();
  }
  // 进入收束期时，预填充收束队列
  if (newPhase === 'RESOLUTION') {
    this._fillResolutionQueue();
  }
  
  // 发出阶段转换事件 → UI更新 + SceneLayerSystem切换氛围
  eventBus.emit('flow:phaseChanged', { 
    phase: newPhase, 
    prev: this.phaseHistory[this.phaseHistory.length - 1] 
  });
}
```

### 4.6 高潮队列填充

```javascript
_fillClimaxQueue() {
  const realm = gameState.realm;
  const cultivation = gameState.attributes.cultivation;
  
  // 1. 章节里程碑卡（必有）
  const milestoneCard = chapterSystem.getMilestoneCard(realm, cultivation);
  if (milestoneCard) {
    this.climaxQueue.push(milestoneCard);
  }
  
  // 2. 弧线高潮卡（如果有待触发的高潮）
  const arcClimax = storyNetworkSystem.getClimaxCard();
  if (arcClimax) {
    this.climaxQueue.push(arcClimCard);
  }
  
  // 3. 因果大爆发（如果因果种子积压超过5个）
  const pendingKarmas = karmaSystem.getPendingBlooms(5);
  if (pendingKarmas.length > 0) {
    const karmaCard = karmaSystem.buildBloomCard(pendingKarmas[0]);
    this.climaxQueue.push(karmaCard);
  }
}
```

## 五、玩家可读性设计

### 5.1 阶段可视化

玩家不需要知道"FlowDirector"这个词，但必须**感受到**阶段变化：

| 阶段 | UI表现 | 玩家感知 |
|------|--------|----------|
| CALM | 顶栏显示"修行日常"标签，背景偏暖色 | "现在是安全期，可以搞资源" |
| BUILDUP | 顶栏显示"暗流涌动"标签，背景色调微变 | "事情开始多了" |
| TENSION | 顶栏显示"危机将至"标签，背景偏冷，修为条闪烁 | "要出大事了，做好准备" |
| CLIMAX | 顶栏显示"关键时刻"标签，全屏边框变色 | "这是重要剧情" |
| RESOLUTION | 顶栏显示"尘埃落定"标签，背景恢复暖色 | "刚经历了一场大事，喘口气" |

### 5.2 卡牌来源标签

每张卡牌显示一个小标签，告诉玩家它从哪来：

```
┌──────────────────────────────┐
│ 【旧识来访】         ⚡因果   │
│                              │
│ 一只白狐拦住你的遁光...       │
│                              │
│ (此事与炼气期救过的妖兽有关)   │
│                              │
│  ← 拒之    纳之道侣 →         │
└──────────────────────────────┘
```

标签类型：
- `⚡因果` — 因果种子发芽（来自 KarmaSystem）
- `📜主线` — 章节里程碑（来自 RealmChapterSystem）
- `🎭支线` — 支线任务卡（来自 QuestSystem）
- `💜道侣` — 道侣事件（来自 CompanionSystem）
- `⚖️势力` — 势力事件（来自 FactionSystem）
- `👤偶遇` — NPC遭遇（来自 NpcSystem）
- `🛒坊市` — 商店/集市
- `⚔️战斗` — 战斗卡
- `✨日常` — 普通卡池

### 5.3 短期目标提示

在顶栏修为条下方，显示当前阶段的下一步目标：

| 阶段 | 目标提示文案 |

## 六、秘境系统重构（关卡设计核心）

### 6.1 秘境 = 卡牌游戏里的"关卡"

当前秘境是线性管道（入口→事件→战斗→奖励），这不是关卡设计。真正的秘境应该像杀戮尖塔的地图节点 — 有路径选择、有风险/回报权衡。

### 6.2 秘境节点类型

| 节点类型 | 图标 | 内容 | 设计意图 |
|----------|------|------|----------|
| `ENTRY` 入口 | 门 | 进入秘境的叙事卡 | 交代秘境背景 |
| `COMBAT` 战斗 | 剑 | 战斗卡（有预警） | 消耗资源，测试Build |
| `ELITE` 精英 | 骷髅 | 高难度战斗，奖励更好 | 风险/回报选择 |
| `EVENT` 事件 | 问号 | 随机事件（选择决策） | 叙事多样性 |
| `TREASURE` 宝箱 | 宝箱 | 获取法宝/丹药/灵石 | 奖励节点 |
| `REST` 休息 | 篝火 | 恢复气血/道心 | 节奏调节 |
| `FORK` 分叉 | 岔路 | 选择走哪条路 | 玩家主动权 |
| `BOSS` Boss | 王冠 | 秘境最终战斗 | 高潮 |
| `EXIT` 出口 | 门 | 结算+离开 | 收束 |

### 6.3 秘境地图结构示例（古洞探险）

```
                    [TREASURE:上古遗宝]
                    /
[ENTRY] → [EVENT] → FORK ── [COMBAT] → [REST] ── \
                    \                           → [BOSS] → [EXIT]
                    [ELITE] → [TREASURE:妖丹] ──/
```

玩家在 FORK 节点选择上路（宝箱+战斗+休息）或下路（精英+宝箱），两条路最终汇合到 Boss。

### 6.4 秘境数据结构（图格式）

```json
{
  "id": "ancientCave",
```

## 七、战斗系统融入Flow Director

### 7.1 当前问题

战斗卡从普通卡池抽出后直接进入战斗，没有预警、没有准备、没有空间感。

### 7.2 战斗作为"中断事件"

在 FlowDirector 架构下，战斗不再是普通卡池的一部分，而是由阶段和情境驱动的**中断事件**：

```
FlowDirector 判断当前阶段 → 是否应该有战斗？
  TENSION 阶段 → 30%概率出现战斗预警卡
  CLIMAX 阶段 → Boss战斗（里程碑驱动）
  DUNGEON 阶段 → 秘境节点决定的战斗
  CALM/BUILDUP → 极低概率(5%)遭遇战
```

### 7.3 战斗预警 → 战斗 → 战后收束

```
[TENSION阶段] 
  → FlowDirector 抽到战斗来源 
  → 插入"战斗预警卡"（COMBAT_WARNING 类型）
    → 玩家选择：迎战 / 备战 / 撤退
      → 迎战：直接进战斗
      → 备战：消耗丹药buff，然后进战斗
      → 撤退：损失修为/道心，避免战斗
  → 战斗结束
  → 自动转入 RESOLUTION 阶段（战后喘息）
```

## 十、关键设计决策记录

### Q1：为什么不用 CardSystem 现有的9级优先级链做基础？

因为9级链是**静态优先级**，无法响应玩家状态变化。高优先级的叙事卡永远排在前面，低优先级的NPC卡永远排在后面。FlowDirector 的阶段系统是**动态权重**，CALM阶段NPC遭遇卡有5%概率出现，TENSION阶段叙事卡权重自然升高。这更接近王权的 Bag 系统。

### Q2：为什么保留秘境作为独立阶段，不融入阶段系统？

因为秘境是**锁入模式**（借用王权的概念）。玩家进入秘境后，主循环暂停，秘境循环接管。退出后恢复主循环。这和战斗一样，是中断性质的。

### Q3：为什么不把所有卡牌都放进一个Bag？

因为一念仙途的系统复杂度远超王权。王权只有4维属性+一个Bag，一念仙途有5维属性+6种功法+因果系统+支线+秘境+战斗+叙事弧线。全部塞进一个Bag会导致权重计算过于复杂，且无法保证关键叙事（如里程碑）一定会出现。FlowDirector 的阶段系统是折中方案 — 在阶段内用权重Bag，在阶段间用确定性转换。

### Q4：旧数据怎么兼容？

- 普通卡：无变化，仍走 CardSystem._drawNormal()
- 叙事卡：从"推到队列"改为"被 FlowDirector 查询"。StoryNetworkSystem 需要新增 `getCard()` 方法替代直接推卡
- 秘境：图格式新数据，旧数组格式自动向后兼容
- 战斗卡：从普通卡池中移除 `type:COMBAT` 标记的卡，改由 FlowDirector 在 TENSION 阶段按概率触发
