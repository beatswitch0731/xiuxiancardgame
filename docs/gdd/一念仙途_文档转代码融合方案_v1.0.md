## 二、目标架构

### 2.1 核心原则

```
「内容与逻辑分离」：所有角色、卡牌、对话、事件数据 = JSON数据文件，不硬编码
「系统即模块」   ：每个设计文档中的系统 = 一个独立的JS类模块
「事件总线通信」  ：模块之间通过EventBus通信，不直接耦合
「渐进式接入」    ：5个阶段，每阶段可独立运行+验证，不破坏上一阶段
「UI面板注册制」  ：新UI面板通过注册机制挂载，不修改现有HTML结构
```

## 三、数据管线

**所有文档内容通过「JSON洗数据」步骤转化为游戏可用格式。**

### 3.3 DataLoader 设计

```javascript
class DataLoader {
  constructor() {
    this.cache = new Map();
    this.pendingLoads = new Map();
  }

  // 加载指定数据模块（懒加载）
  async load(moduleName) {
    if (this.cache.has(moduleName)) return this.cache.get(moduleName);
    if (this.pendingLoads.has(moduleName)) return this.pendingLoads.get(moduleName);

    const loadPromise = this._fetchAndParse(moduleName);
    this.pendingLoads.set(moduleName, loadPromise);
    const data = await loadPromise;
    this.cache.set(moduleName, data);
    this.pendingLoads.delete(moduleName);
    EventBus.emit('data:loaded', { module: moduleName, count: this._countItems(data) });
    return data;
  }

  // 预加载一系列模块
  async preload(moduleNames) {
    return Promise.all(moduleNames.map(name => this.load(name)));
  }

  _fetchAndParse(moduleName) {
    // 在纯HTML环境下，从内联<script>标签或fetch加载
    // 优先用内联数据（DATA_MODULES 全局变量），次选 fetch
    if (typeof DATA_MODULES !== 'undefined' && DATA_MODULES[moduleName]) {
      return Promise.resolve(DATA_MODULES[moduleName]);
    }
    // Fallback: fetch（需要本地服务器运行）
    return fetch(`data/${moduleName.replace(':', '/')}.json`)
      .then(r => r.json());
  }
}
```

**在实际开发中，我们会把所有JSON数据内联到一个`<script>`标签中**（因为双击打开HTML文件时fetch跨域限制），这样DataLoader直接从DATA_MODULES全局变量读取，无需服务器。

### 4.1 EventBus

所有模块通信的唯一通道：

```javascript
class EventBus {
  constructor() {
    this._listeners = {};
  }

  on(event, callback) { /* 注册监听 */ }
  off(event, callback) { /* 移除监听 */ }
  emit(event, data) { /* 触发事件 */ }
}

// 事件命名规范：领域:动作
// 示例：
// 'card:drawn'        → 卡牌被抽出
// 'card:chosen'        → 玩家做出选择
// 'state:attributeChanged' → 属性变化
// 'state:death'        → 玩家死亡
// 'npc:met'            → 首次遇到NPC
// 'npc:affectionChange'→ 好感度变化
// 'quest:triggered'    → 支线触发
// 'quest:completed'    → 支线完成
// 'companion:event'    → 道侣事件触发
// 'world:rumor'        → 新情报产生
```

## 六、防冲突设计

### 6.1 系统间的数据主权

**铁律：每个字段只有一个"Owner"系统，其他系统只能读，不能写。**

| 数据 | Owner | 读取者 |
|------|-------|--------|
| 属性(cultivation等) | GameStateManager | 所有系统 |
| flags | GameStateManager | QuestSystem(写), CardSystem(读) |
| 好感度 | NPCSystem | CompanionSystem, DialogueEngine, QuestSystem |
| 秘密解锁 | NPCSystem | DialogueEngine, RumorSystem |
| 羁绊等级 | CompanionSystem | NPCSystem(只读) |
| 因果种子 | KarmaSystem | QuestSystem(注入), CardSystem(抽取) |
| 支线状态 | QuestSystem | CardSystem(抽卡介入) |
| 势力关系 | FactionSystem | RumorSystem, WorldEventSystem |

### 6.2 抽卡优先级

多个系统都可能想"插入"卡牌。优先级顺序：

```
1. 死亡卡 (GameState: 玩家死亡，必须出)          优先级: 100
2. 瓶颈卡 (CardSystem: 修为满，必须出)            优先级: 90
3. 支线当前卡 (QuestSystem: 支线进行中)           优先级: 80
4. 支线入口卡 (QuestSystem: 新支线触发)           优先级: 70
5. 因果卡 (KarmaSystem: 因果种子发芽)             优先级: 60
6. 道侣事件卡 (CompanionSystem: 随机触发)         优先级: 50
7. 世界事件卡 (WorldEventSystem: 全局事件)        优先级: 40
8. NPC-NPC互动卡 (NPCSystem: 两个NPC碰面)        优先级: 30
9. 普通卡 (CardSystem: 按权重随机)                优先级: 10
```

**防冲突规则**：同一轮只出一张卡。多个系统同时请求 → 选优先级最高的。同优先级 → 按注册顺序FIFO。

### 6.3 事件调度

```javascript
// CardSystem.draw() 的重构后逻辑
draw() {
  const requests = EventBus.collect('card:request', { gameState: this.state });
  // requests = [{ source, priority, cardId }, ...]
  requests.sort((a, b) => b.priority - a.priority);
  return requests[0]?.cardId || this._drawNormal();
}
```

## 七、内容生成工作流

### 7.1 设计师→数据→代码的闭环

```
你（设计师）修改设计文档
        ↓
AI 提取文档中的新内容 → 生成 JSON 数据 → 放入 data/ 目录
        ↓
你运行游戏 → DataLoader 自动加载新 JSON → 新内容自动生效
        ↓
你玩到不满意的地方 → 告诉 AI → AI 修改 JSON → 刷新即生效
```

### 7.2 常用的增量更新场景

| 你要做的事 | AI 生成什么 | 放哪里 |
|-----------|------------|--------|
| "加10张炼气期卡牌" | 10条卡牌JSON | data/cards/qi_condensation.json（追加）|
| "给白刃真人加20句对话" | 20条对话JSON | data/npcs/npc_dialogue.json（追加）|
| "新支线：铁剑翁的秘密" | 支线定义+卡牌JSON | data/quests/iron_sword.json（新文件）|
| "调整金丹期卡牌权重" | 修改卡牌weight字段 | data/cards/golden_core.json（覆盖）|
| "加5个道侣事件" | 5条事件JSON | data/companions/companion_events.json（追加）|

### 7.3 如何避免数据重复和冲突

**原则**：每一类数据放在唯一的一个JSON文件中，不跨文件引用同样的数据。

| 场景 | 正确做法 | 错误做法 |
|------|---------|---------|
| 卡牌中提到NPC | `"npcReference": "bai_ren"` | 在卡牌JSON里重新写一遍白刃真人的数据 |
| 支线卡牌 | 放在支线JSON（quests/*.json） | 放在cards/*.json |
| 多人引用同一个对话 | 放在npc_dialogue.json，按scene索引 | 在多个地方重复写同一句对话 |
