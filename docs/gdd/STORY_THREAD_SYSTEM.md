# 故事线程系统 (Story Thread System)

> 解决"选了卡但没有因果故事感"的核心设计问题。

## 1. 问题诊断

### 1.1 根因分析

审计了全部 306 张卡牌、CardSystem 抽卡逻辑、StoryNetworkSystem 叙事编排、game.js 主循环。发现四个层面的割裂：

| 层面 | 当前状态 | 问题 |
|------|---------|------|
| **数据层** | 每张卡是独立原子事件，`nextCard` 仅使用 ~10 次 | 卡与卡之间无结构关联 |
| **抽取层** | 按 type 优先级随机抽卡，NORMAL 卡从同境界池中纯随机 | 相邻两张卡无因果逻辑 |
| **编排层** | StoryNetworkSystem 只做"什么时候出什么类型的卡" | 不保证内容层面的连贯性 |
| **呈现层** | UI 每次只显示当前卡，无历史/上下文 | 玩家看不到"这是什么故事的延续" |

### 1.2 具体表现

```
炼气期玩家 3 回合的实际体验：
  回合 1: "受伤修士求助" → 选择帮他 → cultivation +5
  回合 2: "宗门发布任务" → 选择接取 → spiritStone +15  
  回合 3: "坊市闲逛" → 选择淘宝 → 买到丹药

玩家感受：三件事之间毫无关系。我帮了那个修士，然后呢？他消失了。
        宗门任务是为了什么？杀完妖兽世界没有任何变化。
        坊市闲逛就是纯随机事件。
```

### 1.3 现有叙事系统的局限

- **KarmaSystem（因果种子）**：种子种植→若干回合后发芽→生成单张 KARMA 卡。但发芽是一次性的，不是持续叙事。
- **NarrativeSurfacing（叙事浮现）**：每 5 回合检查系统阈值，生成单张浮现卡。仍然是原子事件。
- **ChoiceEchoEngine（选择回响）**：种下回响种子，生成回响卡。延迟触发但仍是单次。
- **companionArcs（道侣弧线）**：已有弧线框架（起承转合），但仅限道侣关系，且内容与普通卡牌割裂。

---

## 2. 设计目标

1. **因果连贯感**：玩家做选择 → 世界回应 → 产生后果 → 后果引出新事件
2. **叙事节奏**：不是每张卡都是故事线，而是"普通事件卡"穿插"故事线卡"
3. **不破坏现有系统**：与 20 级优先级抽卡兼容，故事线程作为"注入层"而非替代层
4. **轻量级**：不增加开发者每张卡的数据负担，线程定义在单独的 JSON 文件中
5. **可扩展**：新境界只需添加新线程 JSON，不需要改引擎代码

---

## 3. 故事线程引擎架构

### 3.1 核心概念

**故事线程 (Story Thread)**：一个由 2-5 张卡组成的小型叙事弧，有明确的起-承-转-合结构。

```
┌──────────────────────────────────────────────────────┐
│  故事线程生命周期                                      │
│                                                      │
│  DORMANT ──trigger──> ACTIVE ──progress──> CLIMAX    │
│    (等待触发条件)       (卡1-2)    (中间卡)     (高潮卡) │
│                              │                       │
│                              └──resolve──> COMPLETED │
│                                  (结局卡)    (记录日志) │
│                                                      │
│  玩家选择影响方向:                                     │
│  - 每个线程节点有 left/right 分支，导向不同结局        │
│  - 结局可能种下新因果种子，引出新线程                   │
└──────────────────────────────────────────────────────┘
```

### 3.2 系统架构

```
StoryThreadEngine
├── ThreadManager        — 线程生命周期管理
│   ├── activeThreads    — 当前活跃线程 Map<threadId, ThreadState>
│   ├── completedThreads — 已完成线程 Set (用于防重复触发)
│   ├── threadJournal    — 玩家故事日志 (可查看的叙事历史)
│   └── checkTriggers()  — 每回合检查触发条件
│
├── ThreadInjector       — 将线程卡注入主卡牌流
│   ├── inject()         — 注入当前线程的下一张卡
│   └── priority         — 注入优先级 55 (高于NORMAL的10，低于弧线高潮的53)
│
└── ThreadResolver       — 线程结局处理
    ├── resolve()        — 应用结局效果 + 写入日志
    └── plantSequelSeed()— 种下续集因果种子
```

### 3.3 触发条件类型

线程可以多种方式触发：

| 触发类型 | 说明 | 示例 |
|---------|------|------|
| `choice_match` | 玩家在特定卡上做了特定选择 | 在 "受伤修士求助" 卡选了 "帮他" |
| `karma_sprout` | 某个因果种子发芽时 | "荒村秘密" 种子发芽 |
| `state_threshold` | 属性跨越阈值 | 道心 > 50 且 修为 > 30 |
| `npc_affection` | 某 NPC 好感达到阈值 | 虎娘好感 > 15 |
| `realm_enter` | 进入新境界 | 突破到筑基期 |
| `tag_chain` | 基于 tag 链式触发 | 连续 3 张 combat 标签卡 |

{

## 5. 与现有系统的集成

### 5.1 优先级位置

在 20 级优先级抽卡体系中，线程卡注入放在第 55 级：

```
53  道侣弧线高潮卡  ← NPC 剧情优先
52  师尊弧线高潮卡
51  道侣弧线推进卡
──
55  故事线程卡      ← 新位置：在世界叙事之上，在普通事件之上
──
50  道侣事件卡
45  涌现叙事卡
──
10  NORMAL 普通卡   ← 大量普通事件
```

**设计理由**：线程卡优先级高于普通事件（10）但低于角色弧线（50+），保证角色剧情不会被随机事件淹没，同时线程卡给普通卡池注入结构。

### 5.2 注入时机

在 `game.js makeChoice()` 中，当前卡处理完毕后：

```js
makeChoice(direction) {
  // ... 现有逻辑 ...

  // ── 故事线程 ──
  // 1. 检查当前完成的选择是否触发了新线程
  threadEngine.checkTriggers(card, direction, gameState);
  
  // 2. 检查是否有活跃线程需要推进
  const threadCard = threadEngine.getNextThreadCard(gameState);
  if (threadCard) {
    this._narrativeQueue.push({
      card: threadCard,
      priority: 55
    });
  }

  // ... 继续现有逻辑 ...
}
```

### 5.3 线程注入频率控制

```js
// 避免线程淹没正常游戏节奏
const config = {
  maxActiveThreads: 2,          // 同时最多活跃线程数
  minTurnsBetweenNodes: 2,      // 线程节点之间最少间隔回合数
  threadCardRatio: 0.25,        // 线程卡占总卡牌比 ≈25%
};
```

### 5.4 与 KarmaSystem 的交互

线程结局可以种植因果种子，因果种子发芽可以触发新线程：

```
Thread Resolution → plantSequelSeed → KarmaSystem
                                        ↓
                                  (N 回合后发芽)
                                        ↓
                              Karma Sprout → trigger new Thread
```

这形成闭环：**玩家的选择 → 故事线程 → 因果种子 → 延迟后果 → 新故事线程**。

## 6. UI 设计

### 6.1 线程指示器（卡牌 UI）

在卡牌左上角类型标签旁边，添加线程标识：

```
┌──────────────────────────────┐
│ ▎荒村妖道           NORMAL   │  ← 线程色条 + 线程名
│                              │
│  你救下的修士体内有诡异药力   │
│  残留——这附近怕是有妖道在    │
│  作祟。                      │
│                              │
│  [立刻前往荒村]  [先查药引]  │
└──────────────────────────────┘
```

线程色条颜色：紫色（神秘）、红色（危险）、绿色（发现）、金色（天命）

### 6.2 线程日志（侧边面板）

可折叠的侧边面板，显示：

- **活跃线程**：当前正在进行的线程名 + 进度条（2/4）
- **最近完成**：最近完成的 3 个线程的简短摘要
- **因果线索**：从已完成线程种下的、尚未触发的因果种子

### 6.3 线程完成提示

线程结束时，日志区弹出特殊格式的消息：

```
🔗 故事线完成：荒村妖道
你追查受伤修士体内的诡异药力，最终在荒村古井底部发现了被怨念腐蚀的前青云剑宗弟子。
你的选择改变了这个村庄的命运。
——因果种子已种下：「被逐者的怨念」将在未来开花。
```

## 8. 叙事-玩法融合设计规则

在实现过程中，每张线程卡必须满足：

1. **选择 = 价值观选择**：left 和 right 不是"更好的奖励 vs 更差的奖励"，而是"勇敢 vs 谨慎"、"仁慈 vs 功利"、"诚实 vs 欺骗"
2. **后果延迟但可追溯**：线程结局的后果不在当回合完全显现，而是延迟 5-10 回合
3. **选择记忆 > 2 回合**：玩家在 node_1 的选择必须在 node_3 或结局中被明确引用
4. **世界改变**：线程完成后，至少产生一个可观测的世界变化（NPC 对话变化、地点解锁、因果种子）
5. **不强制**：玩家可以忽略线程触发（不选触发卡的那个选项），线程会在 10 回合后自动过期

## 10. 成功标准

- 玩家在炼气期平均经历 2-3 条完整线程
- 线程卡占总卡牌比例 ~25%（每 4 张卡中有 1 张是线程卡）
- 80% 的玩家能正确说出自己经历过的至少 1 条线程的故事
- 线程结局的效果在后续 10 回合内至少被引用 1 次（通过 NPC 对话、世界事件、新卡描述）
