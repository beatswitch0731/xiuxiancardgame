## 修复概览

三项 P1 漏洞全部修复，共计 **4 个文件、6 处修改**。

## 修复 1: DOMContentLoaded 白屏兜底

**文件**: `index.html`

**问题**: 整个 init 链路（NPC 加载→LitPixel→GameLogic→GameUI）无 try/catch。任一环节抛错 → 白屏，玩家看不到任何信息。

**修复**: 整个 `DOMContentLoaded` 回调体包裹 `try { ... } catch (e) { ... }`。失败时渲染错误提示面板，显示错误信息和堆栈，引导玩家刷新或查看控制台。

```javascript
document.addEventListener('DOMContentLoaded', async () => {
  try {
    // ... 全部初始化步骤 ...
  } catch (e) {
    // 渲染错误提示面板，而非白屏
  }
});
```

## 修复 2: draw() null 返回防崩溃

**文件**: `src/systems/CardSystem.js` + `src/game.js`

**问题**: 三条路径可能返回 null：
1. `draw()` 中 deathCardMap 为空 + 所有卡加载失败 → `return null`
2. `_drawNormal()` 中 `q_meditation` 卡也未加载 → `getCard` 返回 null
3. 以上导致 `getCurrentCard()` 返回 null → UI 渲染崩溃

**修复（三层防线）**:

| 防线 | 位置 | 措施 |
|------|------|------|
| 第1层 | `draw()` | `_buildFallbackDeathCard()` — 死亡卡池空时生成通用死亡卡 |
| 第2层 | `_drawNormal()` | `_buildFallbackEventCard()` — 冥想卡也不可用时生成通用修炼卡 |
| 第3层 | `getCurrentCard()` | 内联兜底 — `draw()` 返回 null 时当场构造默认卡 |

三层独立防御，任一层失效都不会导致 null 传递到 UI。

---

## 修复 3: LitPixel 降级优化

**文件**: `index.html`

**问题**: `lpr.init()` 返回 false 后，仍进入 `await Promise.all(...preloadCharacter...)` 循环，8 次抛错被 `.catch()` 吞掉，无实际作用但浪费时间。

**修复**: init 失败时设置全局降级标记 `window._litPixelDegraded = true`，跳过预加载循环。UI 层已有完备的 `_fallbackAvatar` / `_fallbackCardPortrait` 静态贴图回退，无需额外修改。

---

## 验证：三层防御交叉覆盖

```
初始化崩溃 → try/catch → 错误面板 ✓
死亡卡空池 → _buildFallbackDeathCard → 通用死亡卡 ✓
正常池空   → _buildFallbackEventCard → 通用修炼卡 ✓
最终防     → getCurrentCard 内联兜底 → 默认卡 ✓
WebGL失败  → _litPixelDegraded → 静态贴图 ✓
```

任何单一故障都不会导致白屏或 UI 崩溃。
